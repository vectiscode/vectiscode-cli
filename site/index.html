C · WHY LIMITS DRAIN

Every step re-reads
the whole chat.

Claude Code sends the entire conversation with every step: the setup, your messages, every file it read and every tool result. Most of it comes from the cache at a fraction of the price, but in a long chat it adds up, and every compaction throws detail away.

124 units, one chat, 20 compactions

A real chat: 1,636 steps over 18 hours, compacted 20 times. The fresh-chat lines assume each new chat starts from a 5k handoff note and costs 0.23 units to set up, the median for a new chat in these logs.

D · WHAT SAVES

What actually saves,
measured.

Every number here comes from real logs or from a test on a real account, October 2026.

℞WHAT SAVES

  1. Start fresh around 150k, not sooner.

    On the chat above, fresh chats at 150k would have cost 8% less. At 100k the saving is gone: each new chat costs about as much to set up as it saves. vectiscode works this out for your own chats.

  2. Trim what every request carries.

    A new Claude Code chat in these logs started at 72k tokens before the first message, and re-sending that setup was 17% of all usage. Turn off MCP servers a project doesn't use, deny tools you never call, keep CLAUDE.md short.

  3. Keep tool results small.

    Everything a tool returns is written to the cache once and re-read on every later step. Read files in slices, search instead of opening whole files, keep logs and screenshots out unless they're needed. In these logs, tool results were 27% of all Claude usage: file reads 14%, shell commands 8%.

  4. In Codex, start fresh sooner.

    Codex charges nothing extra to put a chat in its cache, so a new chat is cheap: about 0.2% of a Plus 5-hour limit. A small step in a 170k chat costs 0.26%, so once a Codex chat is that long, every step costs about as much as starting over. New input costs the most: 125k tokens the cache hadn't seen took 3.3% in a single step.

  5. Check that it worked.

    Run npx vectiscode compare 2026-10-17 with the day you changed something. It puts the same numbers side by side, per request and per hour.

E · HOW IT WORKS

How it works

  1. STEP 1

    Reads your logs.

    ~/.claude/projects and ~/.codex/sessions, line by line. A month of logs (1.2 GB here) takes about three seconds. Nothing is changed or uploaded.

  2. STEP 2

    Weighs every request.

    Claude Code: each request's tokens at API list prices, checked against Claude Code's own cost records, shown as units. Codex: the real 5-hour and weekly percentages Codex logs after every turn.

  3. STEP 3

    Writes the findings.

    Ranked by what they cost you, each with a fix. --json for your own scripts, compare to check a change.

F · QUESTIONS

Questions

Is a unit a dollar on my bill?

No. Units are API-equivalent dollars, a common scale to weigh requests against each other. Plans are not billed this way.

Does anything leave my computer?

No. There is no account, no telemetry and no network call. The package has no dependencies, so that's easy to check.

Which plans does it work with?

Claude Code on any plan or API key, and Codex on any ChatGPT plan. Codex limit percentages show for plans that have limits.

I use two ChatGPT accounts.

Each account's limit windows are counted separately.

Windows, macOS, Linux?

All three, with Node 22 or newer. Tested on each.

Cursor, Gemini, OpenCode?

Not yet.
